<h2>路由器怎么「持有」多个公网地址，有四种配法</h2>
<p>把多个公网地址配到路由器上，常见四种做法：全部绑在 WAN 口、绑定在多个 WAN 口、用地址下发（桥接）、或者只绑一个其余做映射。</p>
<p>四种做法决定了后面的所有配置方式。选错的话，要么地址用不起来，要么结构复杂到难以排错。</p>

<h2>配法一：全部绑在 WAN 口</h2>
<p>把多个地址都加到同一个外网接口上，路由器自己持有这些地址，内网设备经它出网。配置最少，适合「设备不需要独立地址」的场景。</p>
<p>这种配法的关键点是「源地址选择」。路由器要按规则决定出网时用哪个地址，否则只会用第一个。</p>

<h2>配法二：多个 WAN 口各持一个</h2>
<p>每个外网口绑一个地址，分别接到不同线路或同一线路的不同端口。这种结构清晰，适合需要按接口区分流量的场景。</p>
<p>代价是需要设备有足够的外网口，且路由表要按接口区分。口数不够时，可以用 VLAN 在单口上划出多个逻辑接口。</p>

<h2>配法三：桥接或地址下发</h2>
<p>路由器不做地址转换，把公网地址直接透传给内网设备，设备自己持有公网地址。这种结构最「干净」，地址身份最彻底。</p>
<p>但对路由器能力要求高，需要支持桥接或二层透传，且内网设备的配置要跟着改。适合设备数量少、可控性强的场景。</p>

<h2>配法四：一个地址 + 端口映射</h2>
<p>只把主地址绑在路由器上，其余地址通过映射或一对一转换分配给内网设备。这种方式兼顾了「省配置」与「设备独立地址」。</p>
<p>但要注意：映射只影响入站，出站的源地址仍由路由器决定。如果要让设备出网时显示它对应的地址，需要用一对一地址转换，而不是普通端口映射。</p>

<h2>路由器上必须配的四项</h2>
<p>一，外网地址与网关。二，路由规则，确保每个地址都能正常收发。三，源地址选择规则，决定哪个流量用哪个地址出。四，管理入口限制，别让路由器本身暴露。</p>
<p>第三项是最容易被省略、也最容易导致「配了但没效果」的一项。没有它，所有流量都从第一个地址出去。</p>

<h2>内网侧的两个设置</h2>
<p>一是地址分配方式。建议关键设备固定绑定，便于后续做规则与追溯。二是限速。多设备共享一条线路，不限速就会出现单台跑满的情况。</p>
<p>两项都属于「配一次省很多事」的类型。尤其是固定绑定，多设备场景里价值很高。</p>

<h2>验证顺序</h2>
<p>先测每个地址是否能单独出网，再测内网设备出网时用的是哪个地址，最后测外网能否按预期访问到对应设备。三步做完，才能确认配置符合设计。</p>
<p>顺序不能反。跳过第一步直接测设备，出问题时无法判断是地址问题还是规则问题。</p>

<p>配置顺序建议：先确认地址段与掩码，再配网关，最后做映射或策略。顺序颠倒会让排查变得困难，因为问题可能出在任意一层。每完成一步就验证一次连通性，可以把问题锁定在最小范围内。</p>
<h2>常见问答</h2>
<h3>普通路由器能配多个公网地址吗？</h3>
<p><strong>答：</strong>多数家用路由不支持。需要能配置多地址与策略的设备。</p>
<h3>一定要多 WAN 口吗？</h3>
<p><strong>答：</strong>不一定。单口也能加多个地址，只是区分流量要靠规则。</p>
<h3>映射能让设备出网显示不同地址吗？</h3>
<p><strong>答：</strong>普通端口映射不能。需要一对一地址转换或桥接。</p>
<h3>配好后设备出网还是同一个地址？</h3>
<p><strong>答：</strong>查源地址选择规则有没有配。没有配就会全用第一个。</p>
